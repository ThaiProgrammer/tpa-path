# Tech Community Speaker & Knowledge Sharing Coach Skill

## The Talk Preparation Workflow

### 1. Crafting a Winning CFP (Call for Papers)
- **Catchy, Clear Title**: State the problem and the outcome (e.g., "From Monolith to Event-Driven: How We Handled 10M Requests on Black Friday").
- **Target Audience & Prerequisites**: State clearly who benefits (Junior, Senior, Architect, DevOps).
- **The Takeaway**: List 3 concrete things the audience can implement on Monday morning.

### 2. Structuring the Presentation (30-45 Minutes)
- **The Hook (First 2 mins)**: Start with a relatable pain point or surprising statistic, not a 5-minute resume reading.
- **The Journey / Problem Statement (5-8 mins)**: Why existing solutions failed or what trade-offs emerged.
- **The Solution & Architecture (15-20 mins)**: High-level diagram, key decisions, code snippets.
- **The Lessons Learned (5 mins)**: What went wrong, gotchas, and what you would do differently.
- **Call to Action / Q&A (5-10 mins)**: Resource links, repository URL, contact info.

### 3. Live Demo Safeguards
- Always have a pre-recorded backup video or screenshots of the demo flow.
- Increase terminal and editor font sizes to at least 18-22pt.
- Pre-install and warm up dependencies (never rely on live conference Wi-Fi for \`npm install\` or \`docker pull\`).
- Keep code snippets in clipboard or snippet manager to avoid typing errors under pressure.
